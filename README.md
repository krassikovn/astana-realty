# Астана · три квартиры BI Group

Сайт для выбора квартир: каталог ЖК BI Group с визуалами, 3D-карта с инфраструктурой и объявлениями Крыши, подбор трёх квартир, аналитика аренды.

```bash
npm install
npm run dev     # http://localhost:5177, данные уже лежат в public/data
```

Данные собираются один раз и дальше используются с диска:

- `npm run fetch` собирает только то, чего ещё нет (BI Group, Krisha, OSM), уже собранное пропускает.
- `npm run update` принудительно обновляет всё; `npm run fetch:bi`, `fetch:krisha`, `fetch:osm` обновляют части по отдельности.
- `npm run analyze` пересчитывает аналитику аренды по уже скачанным объявлениям, без сети.
- Каждый `fetch:krisha` добавляет снимок ставок аренды в `public/data/history.json`: так копится своя история по ЖК.
- Главные фото ЖК сохраняются в `public/img/projects`; планировки квартир остаются ссылками на CDN BI.
- `public/data/renthistory.json` собран вручную: официальный помесячный ряд аренды в Астане (Бюро нацстатистики, ноябрь 2023 — октябрь 2026) и медианы из обзоров Крыши, со ссылкой на источник каждой точки. Сборщик его не трогает; новые месяцы нужно дописывать из бюллетеней stat.gov.kz.
- `npm run build` собирает статический сайт в `dist/`.

Сайт опубликован на GitHub Pages: https://krassikovn.github.io/astana-realty/ . `npm run deploy` собирает его и заливает в ветку `gh-pages`; исходники лежат в ветке `main`.

Опубликованный сайт закрыт паролем. При `npm run deploy` данные из `public/data` сжимаются и шифруются (`scripts/encrypt.mjs`: AES-256-GCM, ключ из пароля через PBKDF2), в браузере они расшифровываются после ввода пароля. Пароль лежит в файле `.site-password` в корне проекта (в репозиторий не попадает) или задаётся переменной `SITE_PASSWORD`; чтобы сменить пароль, поменяйте файл и опубликуйте заново. Сами данные (`public/data`) в репозитории не хранятся: они собираются командой `npm run fetch`. Фотографии ЖК в `public/img` и код сайта не шифруются.

Подбор считается в браузере на лету, сервер не нужен.

- «Базовый подбор» на обзоре зафиксирован: одна 3-комнатная для жизни и две 2-комнатные под аренду, 65 и 50 млн ₸, левый берег.
- «Мой подбор» строится по анкете (`#/start`, `src/pages/Start.jsx`): сколько квартир, какая для жизни и какие под аренду, бюджет и допустимый выход за него, класс, срок, потолки, обязательные условия, близость квартир, берег, важность критериев и что нужно рядом. Ответы превращаются в настройки движка в `src/profile.js`, сам движок — `src/scenarios.js`.
- Настройки хранятся в браузере каждого посетителя. Кнопка «Поделиться моим подбором» даёт ссылку `#/?cfg=…`, которая открывает тот же подбор у другого человека.

Язык и валюта выбираются в боковом меню и запоминаются в браузере.

- Интерфейс на русском и чешском. Русские строки в коде служат ключами: `t('Каталог ЖК')` из `src/i18n.js` ищет перевод в словарях `src/i18n/cs.*.js`. Непереведённые строки в чешском режиме собираются в `window.__i18nMissing`.
- Цены в данных всегда в тенге. Компонент `Money` из `src/money.jsx` показывает сумму в выбранной валюте (₸, € или Kč), а две другие — во всплывающей подсказке. Курс берётся у Нацбанка Казахстана: `npm run fetch:rates` обновляет `public/data/rates.json`.
- Тексты застройщика с лендингов BI, названия объектов из OpenStreetMap и заголовки объявлений Крыши не переводятся.

Лендинги bi.group (описания, рендеры, особенности, дворы, ход стройки) закрыты проверкой Cloudflare и скриптом не скачиваются. Они собраны один раз через обычный браузер: вкладка bi.group прочитала 54 лендинга и передала сырые данные в `data-raw/landings/` через `scripts/landings-receiver.mjs`. `node scripts/fetch.mjs landings` пересобирает из них `public/data/landings.json` без сети. Картинки лендингов остаются ссылками на `s3.bi.group`.

Данные BI берутся из открытого API каталога (`apigw.bi.group/sales-picker`) и из `__NEXT_DATA__` лендингов, Krisha из `ajax-map-list` и Индекса Крыши, инфраструктура из OpenStreetMap (Overpass). Карта: MapLibre + OpenFreeMap.
